# 招财 Smart：对话体验与 Markdown 规则

适用于 `/portfolio/project/zhaocai-smart/`。本轮目标是完成六章重构、核对交互与布局后，更新既有作品集原网址；本文件定义交付要求，不代表本轮已经验证或发布。保留 GKX 及其他项目的现有改动。

## 展示主线

项目范围与任务 → 完整对话 → 三项关键决策 → Markdown 规范 → 看板复用 → 交付边界与复盘。

公开材料包含语义澄清、过程可视化、看板交互、Markdown 分类及页面总览。新的可运行样例用于解释设计规则，不作为历史研究、客户评价、性能数据或验收结果。页面不添加制作工具标签。

| 章节 | 内容职责 | 主要定位 |
| --- | --- | --- |
| 范围与任务 | 项目身份、本人职责、问题拆解与角色任务矩阵；原始首页按需查阅 | `zcs-project-overview` |
| 完整对话 | 只保留一个完整问数演示，覆盖确认、执行、结果、追问、保存及异常恢复 | `zcs-experience-journey` |
| 关键决策 | 分别说明确认口径、等待与中断、结论与依据的采用条件及代价，操作回到同一个演示 | `zcs-clarification` |
| Markdown 规范 | 以渲染结果、源文、规则标注和来源详情直接对照；原稿与扩展规则按需查阅 | `zcs-markdown-system` |
| 看板复用 | 保留看板原稿与添加、排序、合并、撤销的操作；不在末章重复画廊 | `zcs-board-design` |
| 边界与复盘 | 明确设计、产品业务、研发的责任，复盘具体设计判断与验证范围 | `zcs-delivery` |

范围与任务包含 `zcs-business-needs` 子区域，不再另列业务需求章节。删除重复的体验目标卡片、静态界面复刻、单独的异常恢复章、重复交付原稿画廊和长篇评测计划。原始材料放在对应任务的原生 `details` 内，历史色彩保留，不另套紫色舞台。

按用户批注，完整任务演示移除左侧工作区导航及重复统计范围，对话工作区使用整宽；“新建查询”收至顶部，已保存分析仍从结果中的“查看看板”进入。

异常恢复并入等待与控制决策，区分超时、无匹配和用户停止，三个入口均回到完整对话中的相应状态。不同入口共用一个返回来源路径，不新增重复工作区。

## 视觉与布局

- 样式遵循 GKX 当前的中性叙事结构：白色内容面，中性灰画布与必要边界，标题 `#202020`、正文及说明 `#5B5B5B`、边界 `#DEDEDE`。不把旧文档中的浅蓝或紫色变量表作为公共界面依据。
- 招财紫 `#6750C8` 只用于 Smart 品牌、主要操作、当前关键选择与规则命中。普通正文、表头、侧栏、边框、公开案例切换控件保持中性；不再用整块浅紫背景叠加紫灰正文和紫边框。
- 案例宽度 1200px，窄屏左右 16px；主章节自然分隔，桌面间距 200px，移动端 72px。
- 标题在上、说明在下、统一左边缘。章节标题 38px，内容组 26px，小标题 22px，正文 16px / 1.8；产品演示正文遵循 14px / 24px 的回答规范。
- 标题到导语 16px，标题区到正文 32px，主要内容组之间 48px。桌面图文证据参考 `1.8fr / minmax(340px, 1fr)` 与 40px 间距，1120px 及以下回到上下阅读。
- 采用方案先读，并明确适用条件与代价；备选与补充材料使用原生 `details`。不靠图片透明度、灰色滤镜或粗竖线表达方案主次。
- 说明面板 32px 内边距、16px 圆角；界面证据 12px 圆角，完整截图留白桌面 24px、窄屏 16px。图稿等比展示，不拉伸、不补画。
- 控件高度至少 44px，清晰焦点，减少动态效果时禁用非必要动画；表格自身可横向滚动，页面不横向溢出。
- 原始图稿支持查看大图。重复展示以具体规则和局部任务为主。

## 样式组织与兼容

- Smart 叙事层、产品交互层与证据展示分别组织，共用语义变量；不再追加一层补丁覆盖旧的 `complete / editorial / refinement / opening / focus` 链。
- 保留 ProductDemo、查询状态逻辑、连续追问、回答工作台和同页引用导航的行为。样式收敛不改变演示数据、业务判断或来源关系。
- 章节定位继续使用全站 `ProjectLocator` 与导航样式。桌面侧边目录、紧凑屏顶栏目录、Logo → 返回作品顺序及 44px 点击区域沿用当前共用规则。
- 跨章节引用定位具体内容，并提供返回刚才位置；保留源元素焦点、阅读位置、同页 hash 与演示状态，支持浏览器前进后退。
- 原业务需求与设计目标锚点定位范围任务子区域；`zcs-ai-governance` 与 `process` 定位等待与恢复决策；`zcs-ai-strategy` 与 `zcs-trust-mechanism` 定位末章协作边界。旧 `overview / strategy / clarification / board / markdown` 链接保留映射。

## 对话规则

1. 时间、组织和指标分别识别。未知条件保持待确认，不默认补成当前年份或全集团。
2. 只追问会改变查询结果的条件。利润存在多种合法口径时提供候选，并保留“都不是，补充说明”。
3. 条件不足时禁止执行。补充时保持原问题可见，不要求重新填写全部信息。
4. 问题、条件与执行阶段持续保留；停止、超时和无匹配分别提供恢复入口。
5. 执行状态表示任务阶段，不展示未测量的百分比或预计完成时间。
6. 结果先给结论，再给图表或明细，并保留统计期间、组织、指标、来源和查询快照。
7. 连续追问继承明确条件。范围缩小时显示变更；比较对象不明确时先确认。
8. 变更组织需重新查询；不能拿集团数据代替分公司数据。没有原因明细时只描述变化，不推断原因。
9. 保存到看板保留原始查询条件和数据来源；不将追问中的新范围误写入原始结果。

## Markdown 回答契约

| 内容 | 规则 | 核对重点 |
| --- | --- | --- |
| 标题 | 最多三级，逐级组织，不为字号制造跳级 | 标题能概括该段任务 |
| 结论 | 先给可独立阅读的结论，区分事实、依据、建议 | 每个事实与本次返回数据对应 |
| 正文 | 14px / 24px，深色正文与白底 | 不用加粗、提示框替代层级 |
| 数值 | 同一指标精度一致，携带单位、期间与范围 | 先以原始值计算，再统一显示精度 |
| 表格 | 行列标题完整，数值右对齐，长表保留完整列 | 不删掉同比的上年基期来适配宽度 |
| 比较 | 写明比较对象，区分同比、环比与同年季度比较 | 基期、公式、单位可核对 |
| 缺失 | 区分未取得、无匹配、零和不适用 | 缺失值不能替换为 0 |
| 来源 | 结论附近的来源入口指向已登记的具体来源 | 不接受不存在或伪造的引用 |
| 长文 | 摘要先读、主题分段、目录精确定位 | 引用与表格靠近对应结论 |
| 公式 | 说明变量和计算对象 | 中间计算不提前舍入 |

渲染结果与 Markdown 源文使用同一结构数据。新工作台可切换场景、源文和规则标注，来源详情保留查询范围与样例数据。旧八类场景与十二项组件规则继续保留为延伸查阅。
