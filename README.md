# 李家豪作品集网站

这是根据 `李家豪- UI作品集 (1).pdf` 重新整理出的响应式作品集网站原型。

## 当前内容

- `index.html`: 可直接打开的单页作品集网站，已适配电脑端和手机端。
- `CONTENT_GUIDE.md`: 后续修改文案、添加项目、替换项目详情图片时的维护说明。
- `assets/portfolio/`: 早期从 PDF 中导出的项目封面图，目前首页尽量不依赖这些截图。
- `assets/li-jiahao-ui-portfolio.pdf`: 原始作品集 PDF，保留作源文件。
- `assets/li-jiahao-ui-portfolio-web.pdf`: 适合网页加载的优化版 PDF，供网站下载入口使用。

## 推荐推进流程

1. 补齐每个项目的 case study 文案：背景、目标、你的角色、设计过程、关键决策、最终成果、复盘。
2. 从单页首页扩展为多页网站：`index.html` 做首页，每个项目单独做详情页。
3. 项目详情页优先使用网页组件重构：流程、表格、筛选、状态、组件规范、Before / After。
4. 图片只作为少量关键界面佐证，避免整页 PPT 截图堆叠。
5. 增加真实项目成果：上线链接、客户反馈、数据变化、研发协作说明。
6. 部署上线：可使用 Vercel、Netlify 或 GitHub Pages。

## 作品集助手

首页和案例页右侧的小人提供站内导览，点击后展开悬浮对话窗。助手以第三人称介绍 Leo，不冒充本人；项目页提供对应案例的快捷问题，支持询问职责、难点与设计取舍。回答只使用 `app/chat-knowledge.ts` 中的公开内容，并链接到实际引用的案例章节；超出范围时会引导访客回到作品集话题，不启用联网搜索。

首页的四个快捷问题分别覆盖设计能力、工作经历、GKX项目职责和产品研发协作，其中仅项目问题推荐GKX。问候与欢迎语保持通用；询问项目清单时展示多个项目，询问优先阅读哪个案例时推荐GKX。输入区支持多行文本：Enter 发送，Shift + Enter 换行；中文输入法确认候选时不会提交。对话框支持 Esc 关闭、重置对话和按当前案例追问。

连续对话会保存可信知识条目对应的项目与主题，因此推荐GKX后可以直接追问“具体难点是什么”；切换到其他项目或通用能力、经历话题时同步更新上下文。进入另一案例时，“这个项目”指向当前页面，原聊天记录和草稿保留；刷新及浏览器前进后退也会同步当前标签页的会话。回答下方的两个问题随当前话题变化，并跳过已经回答过的同类问题。首页默认推荐GKX，明确询问智能问数、财税跨端或大屏时则推荐相关案例。

消息和草稿仅保存在当前标签页的 `sessionStorage`，从首页进入案例、刷新或返回后仍可继续；重置会清除本次记录。等待回复时，发送按钮切换为停止按钮，停止后保留消息和草稿，并允许重新发送该问题。离开页面时未完成的回复会在恢复后提供重新发送入口，不会自动重放请求。

小人的章节提示保持一句话：页面加载完成后延迟约 1.8 秒自动弹出，滚动停止约 650 毫秒后按当前章节更新；每个章节自动展示一次，6 秒后收起。打开聊天时暂停自动提示，鼠标悬停或键盘聚焦小人时也可查看当前提示；招财 Smart 案例保留聊天入口，自动气泡不遮挡正文。对话框的重置和发送使用图标按钮，悬停重置图标显示文字提示。手机及触摸平板使用底部面板，打开后收起小人；横屏初始问题并排展示，布局跟随可视区域为屏幕键盘留出空间，打开面板不会主动唤起键盘。

需要模型接口时，在本地或服务端复制 `.env.example` 为 `.env.local` 并填写 `OPENAI_API_KEY`（可选填写 `OPENAI_MODEL`），`/api/chat` 会在服务端调用模型，密钥不会进入浏览器。没有密钥或使用 GitHub Pages 静态托管时，界面会自动使用同一份本地白名单知识库回答，仍保持边界限制。

如果静态站点需要连接独立的 API 服务，可在加载主脚本前设置 `window.__PORTFOLIO_CHAT_API__` 为 `POST` 接口地址（并由该服务自行处理跨域）；接口应返回 `{ reply, mode, references }`。

当前人物素材使用 `assets/visual/sidebar-character/assets.json` 配置的透明动画帧。替换角色时保留对应状态映射即可，不需要改聊天和滚动逻辑。
